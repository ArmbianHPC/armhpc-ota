# 网络重连与配置保留

[English](NETWORK-RECONNECT.md)

## System 静态地址与 Rescue DHCP

System 和 Rescue 可以保留不同的网络配置。上位机分别记录经过认证的 System、Rescue 地址和 SSH 端口，
并记住全部物理网口的 MAC；这些记录保存在本地设备清单中，关闭后重新打开上位机仍可使用。

Windows 与 Linux 上位机在重启或断线后采用相同的重连顺序：

1. 尝试当前地址和之前已认证的两个环境地址。
2. 读取电脑的 IPv4 邻居表，优先查找指定范围内与已知设备 MAC 匹配的地址。
3. 扫描 GUI 指定网段或 CLI `--scan-range`，刷新邻居信息后核对候选。
   发现扫描只读取 SSH banner，不发送登录凭据。
4. 未指定网段且已有经认证的 MAC 时，在本机直连的私有 IPv4 网段内有限搜索：前缀 `/22` 至 `/30`，
   总计最多 1,024 个主机地址。更大或经路由访问的网段需要明确指定。
   旧设备记录没有 MAC 时不自动扫描网段，仍可使用显式指定的扫描范围。

MAC 用来寻找候选地址；换 IP 后仍核对已登记的 SSH 主机密钥和原持久设备 ID。
临时忽略所选地址指纹的选项不会扩大到自动发现的新地址。无人值守切换前应登记 System、Rescue 的 SSH 身份。
重连继续查询原任务和请求 ID，不重复创建部署任务。

设备重启会关闭旧 SSH 会话。新环境取得可达地址并启动 SSH 后，上位机恢复任务观察。
MAC 发现不会修改两个环境的 IP、DHCP 服务、路由或防火墙。
跨路由时邻居表可能只能看到网关 MAC，此时使用可达的历史地址或明确指定扫描网段。

## OTA 与普通系统恢复

写入 SATA System 根分区前，设备从旧 System 根目录备份配置，写入后恢复到新根目录，再启动 System。
Rescue 独立备份自己的配置，不把 Rescue 的 DHCP 配置用作 System 配置。

保留的网络资源包括：

- `/etc/systemd/network` 中的 `.network`、`.netdev`、`.link` 和 drop-in；
- `/etc/NetworkManager/system-connections` 中的连接配置；
- `/etc/netplan`、`/etc/network/interfaces` 和 `/etc/network/interfaces.d`；
- `/etc/resolv.conf`、`/etc/systemd/resolved.conf` 及其 drop-in；
- ARMHPC 管理接口、路由策略、已确认网络事务，以及物理网口身份和 MAC 记录。

如果备份包含完整网络配置目录，恢复时以该目录的保存内容替换新镜像相应默认内容，
避免新增且排序靠前的 DHCP 配置抢先匹配静态网口。没有旧目录备份时，保留新镜像默认配置。

普通系统 OTA、Rescue 发起的系统恢复和写入中断后的原任务继续，均使用该保留流程。
尚未确认的网络修改会阻止 OTA，需先确认或回滚。

只通过 `ip address`、`ip route` 临时添加的运行时设置、当前 DHCP 租约，以及保留清单之外的自定义文件，
不等同于已保存的静态配置。整盘重刷 eMMC、首次安装 SATA，与保留旧 System 配置的 OTA／恢复属于不同操作。

## 重连诊断

重启确认和 OTA 任务观察会显示已登记 MAC、可信 SSH 环境、扫描范围、匹配地址和连接结果。已找到地址但登录认证失败、环境指纹未登记，与没有发现地址分别显示；自动发现继续核对指纹和设备 ID。

失效历史地址先经过有界 SSH banner 探测；扫描期间 SSH 就绪后允许在本轮重新尝试。超时结果保留重启前 boot ID 和最后的发现原因，不重新发送重启命令。

## 手动查找当前 IP

在 Windows GUI 中选中已认证的 SSH 设备，按需填写扫描范围，然后点击“发现与登录”中的
**按 MAC 查找 IP**。主动扫描会刷新邻居信息，并显示匹配 IP 与 SSH 就绪状态；没有 SSH
响应的缓存邻居记录会标记为尚未就绪。

只有 SSH 认证、指纹和原持久设备 ID 核对成功后，才更新设备列表中的地址。此手动操作可明确
确认尚未登记的环境指纹；已登记环境的指纹发生变化仍会拒绝。登录失败或取消时保留原地址及
已找到的 IP 列表。“停止扫描”可取消本次扫描和身份查询。操作仅查询状态，保留原部署任务。

## System 与 Rescue 分别使用登录设置

Windows 按 System、Rescue 分别保存 SSH 登录设置，使用 DPAPI 加密，兼容读取旧设备登录记录。
可信的环境指纹会在发送登录凭据前选择对应设置；该环境没有单独设置或账号认证失败时，可使用已经配置的默认登录。
例如 System 使用私钥，Rescue 使用保存的默认密码。指纹无法区分环境时，仅尝试用户明确配置过的
登录设置，且只在 SSH 认证阶段切换，不因此重新执行命令或部署。

只有指纹、环境和原持久设备 ID 核对通过后才记住成功的登录方式。“单台登录设置”修改所选设备
当前环境，保留另一个环境的设置。指纹拒绝与账号认证失败分别显示；MAC 匹配仍需核对 SSH 身份和设备 ID。

## 私钥与密码回退、分环境账户

“默认登录设置”可同时保存私钥、私钥口令及账户密码。每个配置先尝试私钥，认证拒绝或私钥无法加载时，再尝试同一配置中的密码。指纹拒绝、网络故障和命令执行失败不触发认证方式重试；认证回退不会重新提交命令。

“System / Rescue 默认登录”分别保存两种环境的默认用户名、密码和私钥。“单台登录设置”提供 System、Rescue 两个页签，当前在任一环境时均可编辑另一环境的登录设置。勾选要保存的环境，其余保留原设置；各设备独立设置优先于分环境默认值，随后使用通用默认值。

登录配置使用 Windows DPAPI 加密保存在本机，设备端账户不随上位机设置改变。成功认证后保留完整配置，密码认证成功不会丢弃已保存的私钥，私钥认证成功也不会丢弃备用密码。
