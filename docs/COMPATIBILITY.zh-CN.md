# 独立版本与兼容性

[English](COMPATIBILITY.md)

`armbian-hpc` 和 `armhpc-ota` 独立使用 MAJOR.MINOR.PATCH 版本号。准备发布哪个仓库，就修改哪个仓库的版本；另一个仓库无需陪同发版或增加版本号。框架版本用于系统镜像和系统 OTA 包，OTA 版本用于 agent、上位机和 maintenance。

## 构建输入

两个仓库分别在 `COMPATIBILITY.json` 声明要求。构建按数字比较 `minimum_companion_version`，核对源码接口和 OTA 协议，并校验框架显式声明的 `minimum_agent`，不要求两个发布版本相同。例如框架 1.2.1 配 OTA 1.2.2，或框架 1.2.2 配 OTA 1.2.1，只要声明的要求满足，都可以构建。

当前源码基线要求配套源码至少为 1.2.1，这是共享恢复和固件升级资源的构建要求，不代表所有连接设备的系统固件都必须升级到 1.2.1。已发布的 1.2.1 及以前源码没有兼容声明，按旧版源码接口 1、OTA 协议 1 识别；后续源码必须提供显式声明。即使版本号更高，不支持的接口也会被拒绝。

CI 通过 `.github/companion-source.json` 和工作流固定实际验证的配套 commit。固定提交不要求两个仓库同步版本。发行仍从干净、已提交的源码构建，记录各自的 `source_versions` 和 `source_commits`；源码附件按所属仓库版本或精确 commit 命名。

## 设备与包兼容

- 保持 JSON `protocol: 1`、已有命令参数、任务 ID、重连行为和可选字段默认值。兼容新增字段，不要求旧设备提供新字段。
- 新 agent 继续读取受支持的旧签名包和任务记录。旧系统固件在满足板型、布局和运行时要求时，可以安装较新的维护包。
- 包中的 `minimum_agent` 表示实现所需功能的最早 agent 版本。只有功能确实需要时才提高，不能因为构建工具或框架版本增加就自动提高。当前框架声明为 1.2.1；配套 BOOT 固件升级也保留既有的 1.2.1 最低要求。
- 固件版本可以高于兼容的 agent 版本；旧 agent 缺少必需功能时，先安装维护包再部署。
- 保留签名、哈希、架构、板型、布局、启动 ABI、内核/DTB/initramfs/模块配套、容量和活动根保护。独立版本不允许部署不兼容固件，也不绕过发布序号的防回退检查。
- 同一个维护包的签名清单与所含运行时仍须使用一致的 OTA 版本。兼容不代表自动降级 K3s/etcd 数据或恢复旧设备身份。

向下兼容是发行要求：回归检查保留受支持的旧行为；确实无法兼容的变更必须明确提高对应最低要求或接口。不承诺任意未来包或未支持硬件都兼容。
