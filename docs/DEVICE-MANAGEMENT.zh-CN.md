# 设备管理

[English](DEVICE-MANAGEMENT.md)

设备表格显示主机名、MAC 地址、地址/COM、板卡、环境、普通系统及 Rescue 版本、状态、最近命令和返回概况。
已移除“备注”“连接”“时间状态”三列；既有连接配置和时间记录仍保留兼容。
点击设备行只选中该行，不展开详情。完整命令返回内容显示在独立的设备结果面板。

## 不登录的扫描

填写明确的 IPv4 CIDR，点击“扫描 SSH / 主机名”。扫描先发现 SSH 候选，再查询反向 DNS 和同链路 mDNS PTR。
扫描不发送用户名、密码或 SSH 认证消息，名称查询有超时并随停止扫描取消。

设备或路由器需要发布相应记录；查不到时主机名留空，不从 SSH banner 猜测名称。
DNS/mDNS 名称可能带 `.local` 或域名后缀，只作为发现信息。认证后读取实际系统主机名，
并按持久设备 ID、SSH 身份登记；重复扫描不会覆盖已核对的主机名。

## MAC 地址

认证或刷新状态时，通过已有 SSH/串口连接读取物理网口 MAC。
表格优先显示承载当前 SSH 连接的网口；所有网口名称、MAC 和地址可通过上位机 CLI status 的 `network_interfaces` 字段查询。
不显示环回和虚拟网口。本功能只读取设备信息，不要求更新设备 agent。

MAC 不替代设备 ID 或 SSH 身份。上位机 CLI 的 status 在可读取时增加 `mac_address`、
`network_interfaces` 和 `hostname`，保留原有 protocol 1 字段。

## 地址变化后的重连

上位机记住已认证的 System／Rescue 地址及物理网口 MAC，重启后可寻找新的 DHCP 地址，再核对已登记 SSH 身份和原设备 ID。搜索范围、静态网络保留及跨路由说明见[网络重连与配置保留](NETWORK-RECONNECT.zh-CN.md)。

## 选择与删除

支持勾选、Ctrl/Shift 多选、全选可见设备、反选和清空选择。
筛选可匹配主机名、MAC、地址和设备 ID；精确模式只匹配主机名。

点击“删除所选主机”，或在表格中按 Delete，可删除本地候选或已登记主机及对应连接凭据。
默认登录设置保留。设备上的任务和本地原任务记录也保留，重新添加并认证后可以继续观察。
重新扫描可再次发现已移除的主机。扫描、认证或批量操作期间拒绝删除。

## 功能分组

- **设备管理**：日常 ARMHPC 命令、主机名/网络配置、定位灯、重启和单台终端。
- **批量 OTA**：本地推送、工具维护、继续原任务、状态/日志、写盘前取消/重试及 Rescue 恢复。
- **首次接入**：接入预览和首次 OTA 布局接入。
- **开发与诊断**：看门狗故障注入、BOOT 候选/备份、旧更新源拉取、发布工具、指纹绕过及详细时间诊断。

日常命令下拉框不混入开发预置命令。已有 CLI、操作确认、身份核对和写盘限制保持兼容；
看门狗/BOOT 写操作仍限定单台、并发 1，并按原诊断 ID 观察。

命令、接入和 OTA 支持并发 1–8。OTA/接入默认先完成一台试点，失败暂停后续队列。
“停止后续设备”不取消已经提交的设备任务。忽略 unknown 只影响队列推进，未知状态不会改成成功，也不自动重发命令。

Windows 默认及单台登录使用本地加密存储，CSV 不导出凭据。
交互向导使用 SSH/串口终端，同一 COM 不同时交给多个终端占用。

## 配套普通系统试启动恢复

- 节点健康检查明确使用所选 K3s DATA 目录、配置和 CRI 配置。
- 保留 CRI/API 就绪检查，对命令不可用、超时和无效结果返回有界、明确的错误。
- 配套 System 已完整写入、启动健康确认失败时，允许在已确认的新 Rescue 中执行签名工具维护。
- 使用 `armhpc-rescue ota boot resume-system --request-id <BOOT任务ID> --yes --json` 续跑原配套任务，保留任务 ID、配置快照、DATA 和失败历史；核验资源后重新启动验证，不重复写入根文件系统。

续跑前先安装对应签名 maintenance 包，并查询原 BOOT 与 System 任务状态。其他 BOOT 活动阶段、未完成写入、磁盘或包变化、任务不匹配时继续拒绝执行。探针失败不会被当作就绪。
