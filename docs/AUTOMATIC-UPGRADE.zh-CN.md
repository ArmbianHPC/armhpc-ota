# 自动升级

[English](AUTOMATIC-UPGRADE.md)

选择本地签名系统包及需要的工具维护包，认证设备并查询身份、版本、任务和空间。需要工具维护时先完成原维护任务，再继续系统升级。

完整资源经 SSH/SFTP 或串口传输、续传并校验后，提交同一个持久请求。普通系统先重启到已确认 Rescue，再离线写 SATA 系统；Rescue 写备用槽后启动确认。DATA 与身份配置保留。

连接中断后查询原任务，不重复提交新写入请求。重新认证、换 IP 或 COM 接管均需核对持久设备 ID。设备服务独立于上位机窗口运行。

## 取消暂停的上位机任务

在“批量 OTA”页选择设备，点击“取消暂停任务”，核对任务 ID 后确认。此操作只取消处于暂停状态的上位机自动流程；设备端已提交的操作继续执行。它不会回滚升级、停止设备服务或取消设备端任务。

原自动流程、维护和部署 ID、已批准的包绑定、暂停阶段、最近错误和取消时间均保留在本机。点击“自动流程历史”查看所选设备的记录，包括已取消任务；重开软件后仍可查看。已取消流程不会被“继续任务”重新执行，也不再占用上位机的活动自动流程。发起新操作时，仍需核对设备端实际任务和维护状态。

需要取消尚未开始写盘的设备端 OTA 任务时，使用“写盘前取消”，并核对相应设备任务。

日志保留 sequence、boot_id、monotonic_seconds 和设备时间质量，电脑接收时间单独显示。K3s 版本不会被系统 OTA 自动升级。

固件包可以同时签名原始内核／DTB 和候选配套的恢复入口。设备仅按已确认 Rescue 的精确哈希选择并核对 initramfs，将选择绑定到私有恢复备份。未知配套仍在写 BOOT 前拒绝；旧包不会因更新工具而自动获得新的签名基线，需要选择重建包。
